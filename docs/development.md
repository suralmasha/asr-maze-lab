# Разработка

Все команды выполняются из корня репозитория. Для инструментов разработки нужны Node.js 22.13+ в ветке 22.x либо Node.js 24+ и npm. Приложение не требует Node.js или сборки интерфейса.

## Установка и проверки

```bash
make setup-dev
make check
make precommit
```

`make setup-dev` устанавливает зависимости приложения, инструменты проверок и Git-хук pre-commit. Установка требует интернета, последующие проверки работают локально.

| Команда                                     | Назначение                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| `make test`                                 | Python-тесты на временных данных                                               |
| `make lint`                                 | Линтеры и проверка форматирования Python, JavaScript, HTML, CSS и документации |
| `make format`                               | Автоисправления Ruff и форматирование Ruff и Prettier                          |
| `make check`                                | Линтеры и тесты                                                                |
| `make precommit`                            | Хуки для всех отслеживаемых файлов, включая поиск секретов                     |
| `make evaluate ARGS="--dataset evaluation"` | Оценка сохраненной модели на отдельных WAV; [подробнее](evaluation.md)         |

Хуки проверяют подготовленные файлы через Ruff, ESLint, HTMLHint, Stylelint, Prettier и `detect-secrets`. Они не исправляют файлы автоматически. После `make format` проверьте diff и повторно подготовьте файлы к коммиту.

GitHub Actions проверяет Python 3.10 с диапазонами зависимостей и Python 3.12 с версиями из `requirements/locked-py312.txt`. Для проверок интерфейса используется Node.js 22; версии инструментов закреплены в `package-lock.json`.

## Структура

- `src/` - HTTP-сервер, обработка аудио, обучение, кеш и история моделей.
- `web/` - семь HTML-страниц, локальные JavaScript и CSS. Сервер раздает их без префикса `web/` в URL.
- `scripts/` - консольные обучение, визуализация и оценка.
- `tests/` - автоматические проверки Python.
- `config/` - [параметры лаборатории](configuration.md) и конфигурация линтеров интерфейса.
- `requirements.txt`, `requirements/` - зависимости приложения, разработки и зафиксированные версии для CI.

## Данные и режимы

| Путь                            | Содержимое                                   |
| ------------------------------- | -------------------------------------------- |
| `dataset/{up,down,left,right}/` | Исходные WAV: 16 кГц, mono, 16-bit PCM       |
| `models/keyword_classifier.npz` | Активная модель                              |
| `models/lab_settings.json`      | Примененные настройки и версия датасета      |
| `models/cache/`                 | Дисковый LRU-кеш предрасчета                 |
| `models/history/`               | Модели и настройки сохраненных экспериментов |

- `make server` рассчитывает результаты по запросу и сохраняет последнюю модель.
- `make server-cache` дополнительно сохраняет результаты и историю моделей. На этапах шумоподавления и признаков сначала готовятся варианты выбранной записи, затем остальных; пользовательский запрос имеет приоритет. «Звук» и «Сравнение» рассчитываются по запросу в обоих режимах.
- Лимит кеша в поставке - 400 МБ. При заполнении фон приостанавливается, новые запросы вытесняют давно использованные результаты. Кнопка очистки кеша не удаляет WAV и модели.
- Повторное обучение с тем же датасетом и настройками активирует сохраненную модель. Изменение имен или содержимого WAV сбрасывает кеш и историю режима предрасчета, включая его активную модель.

## Границы автоматических проверок

- Локальные проверки выполнялись на macOS с Python 3.12 и Chromium. Linux, Windows и другие браузеры локально не проверены.
- В Chromium проверены семь страниц на ширине 1440 и 390 px, отсутствие ошибок JavaScript, внешних запросов и горизонтального переполнения. На подставном аудио проверены запись, обучение, распознавание и движение робота.
- Автоматизация с подставным аудио не проверяет настоящий микрофон. Синтетические тесты проверяют вычисления и взаимодействие компонентов, а не качество на человеческой речи.
- После изменения обработки звука обучение и распознавание должны использовать одинаковые признаки.
