# Ограничения выполнения

Здесь зафиксированы технические ограничения проекта и причины решений, которые важно сохранять при дальнейшей разработке.

## Построение графиков без оконного интерфейса

### Причина

Лаборатория строит графики для браузера и сохраняет их в PNG. Отдельные окна Matplotlib для этих сценариев не нужны.

При автоматическом выборе backend Matplotlib может использовать нативную оконную подсистему. В фоновом процессе, изолированном окружении или окружении без доступной графической сессии ее инициализация может быть недоступна. Наблюдавшийся сбой возникал при создании оконного canvas: нативная библиотека завершала процесс Python сигналом `SIGABRT`. Это аварийное завершение интерпретатора, которое нельзя надежно обработать обычным `try/except`.

Ограничение связано со способом запуска и зависимостью от графической среды, а не с конкретным компьютером или аудиозаписью.

### Принятое решение

В общем модуле [features.py](../src/features.py) до создания графиков явно выбирается неинтерактивный backend `Agg`. Через этот модуль проходят построения графиков сервера, обучения и консольной визуализации. Сервер также явно выбирает `Agg`, а команда тестирования задает `MPLBACKEND=Agg`.

Такой выбор позволяет создавать PNG без инициализации оконной подсистемы и не полагаться на переменные окружения отдельного запуска. Сигнатуры Python API, обработка аудио и HTTP-маршруты этим решением не меняются.

### Последствия и границы

- Графики предназначены для сохранения и отображения в браузере; интерактивные окна Matplotlib не являются поддерживаемым сценарием этих модулей.
- Выбор backend действует на весь процесс Python. Импорт `features.py` выбирает `Agg` и должен учитываться при использовании модулей в стороннем коде или ноутбуке.
- Новые пути построения графиков должны сохранять режим без окон. Не следует возвращать автоматический выбор backend или включать оконный backend в сервере и фоновых задачах.
- `Agg` устраняет зависимость построения графиков от оконной подсистемы, но не защищает от всех возможных сбоев Python и нативных библиотек.

### Проверка и условия пересмотра

При изменении инициализации Matplotlib нужно проверить создание PNG в отдельных процессах с разным порядком импорта модулей: без `MPLBACKEND` и с явно заданным оконным backend в окружении. Проверка должна подтверждать фактический выбор `Agg`, корректный PNG и отсутствие загрузки оконного backend. Отдельно проверяются консольная визуализация и существующие HTTP-сценарии. Команды проекта: `make check` и `make precommit`.

Решение можно пересмотреть при появлении явного требования к интерактивным окнам. Для этого нужен отдельный сценарий с доступной графической сессией и соблюдением требований выбранного GUI backend к потокам. После изменения необходимо сохранить и проверить работу сервера, консольных скриптов и тестов без графической сессии.

Справочник: [backend Matplotlib и способы их выбора](https://matplotlib.org/stable/users/explain/figure/backends.html).
