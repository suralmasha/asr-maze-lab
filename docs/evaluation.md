# Проверка качества на новых записях

Инструмент оценивает уже сохраненную модель без обучения. Результаты имеют смысл только для того набора реальной речи, на котором выполнена проверка. Репозиторий не содержит опубликованных результатов качества или готового речевого проверочного набора.

## Подготовка набора

1. Обучите модель на записях из `dataset` и завершите подбор параметров.
2. Запишите новые примеры четырех команд. Не копируйте обучающие WAV и не используйте их аугментации. Для сравнения моделей подготовьте один набор и больше его не меняйте.
3. Создайте отдельный каталог `evaluation` с четырьмя папками `up`, `down`, `left`, `right`. В каждой должен быть хотя бы один WAV соответствующей команды. Используйте одинаковое число примеров каждого класса; для более устойчивой оценки соберите больше записей.
4. Сохраните WAV в формате PCM 16-bit, mono, 16000 Гц. В поставляемой конфигурации принимается длительность 0,4-5,5 секунды; границы задаются `audio.min_seconds` и `audio.validation_max_seconds` в [конфиге](configuration.md). Пустые, слишком тихие и поврежденные записи отклоняются. Папки классов должны содержать только WAV, без вложенных каталогов; регистр расширения не важен.
5. Если проверяете работу на новых людях, полностью отделите дикторов обучения от дикторов проверки. Для проверки личной модели отделите хотя бы сессии записи. Зафиксируйте число дикторов, микрофон, шум и условия в сопроводительной заметке без персональных данных.

## Запуск

Из корня проекта после установки зависимостей:

```sh
make evaluate ARGS="--dataset evaluation"
```

Выбор конкретной модели и пути отчета:

```sh
make evaluate ARGS="--dataset evaluation --model models/keyword_classifier.npz --output reports/evaluation.json"
```

По умолчанию существующий отчет защищен от перезаписи. Путь отчета не должен быть символической или жесткой ссылкой на другой файл; такие пути отклоняются даже с `--overwrite`. Для осознанного обновления:

```sh
make evaluate ARGS="--dataset evaluation --overwrite"
```

Команда вызывает `scripts/evaluate_model.py`. Аргументы: `--dataset` обязателен, `--model` по умолчанию указывает на `models/keyword_classifier.npz`, `--output` - на `reports/evaluation.json`, `--overwrite` разрешает перезапись JSON. Ошибка входных данных завершает команду с ненулевым кодом, без отчета по неполному набору. Инструмент работает локально, использует параметры признаков из NPZ и не изменяет модель.

## Чтение отчета

- `accuracy`: доля правильных ответов, от 0 до 1.
- `labels`: порядок классов в матрице ошибок.
- `confusion_matrix`: строки - истинные команды, столбцы - предсказанные; диагональ содержит правильные ответы.
- `per_class`: число примеров (`support`), точность положительных предсказаний (`precision`), доля найденных примеров класса (`recall`), их гармоническое среднее (`f1`). Если класс ни разу не предсказан, его precision и f1 равны 0.
- `predictions`: ожидаемый и полученный класс каждого файла, относительное имя и SHA-256 содержимого.
- `model_sha256`, `feature_version`, `settings`: отпечаток модели и сведения о способе извлечения признаков. У исходной модели версии 1 поле `settings` равно `null`: используются исходные признаки проекта.
- `environment`: версии Python, NumPy, SciPy и scikit-learn для повторения вычислений.
- `overlap_check`: число уникальных текущих обучающих WAV, с которыми проверены побайтовые совпадения.
- `limitations`: ограничения проверки независимости данных.

Сравнивайте отчеты только с одинаковым составом и SHA-256 проверочных файлов. Отчет содержит имена файлов, поэтому не включайте в них персональные данные. WAV игнорируются Git; перед публикацией JSON проверьте имена и право делиться результатами.

## Ограничения

Оценка отклоняет побайтовые дубликаты внутри проверочного набора и совпадения с текущими WAV из локального `dataset`. Это не доказательство независимости: модель не хранит SHA-256 исходных WAV, обучающий каталог мог измениться, а перекодированная или обработанная копия имеет другой отпечаток. Историю происхождения файлов и разделение дикторов проверяет автор набора.

Не используйте проверочный набор для подбора параметров: иначе он станет валидационным, и для итоговой оценки понадобятся новые записи. Высокая accuracy на нескольких примерах одного человека не подтверждает качество на других людях, микрофонах и шуме. Модель всегда выбирает одну из четырех команд: эти метрики не проверяют отказ на тишине или посторонних словах.

Автоматические проверки на синусоидах подтверждают работоспособность вычислений и CLI. Они не измеряют распознавание речи и не заменяют проверку настоящего микрофона.
