# «Научи робота слышать» — офлайн-мастер-класс на 40 минут

Один ноутбук, один микрофон, проектор. Школьникам **не нужно знать программирование**.

## Что входит

| Этап | Готовый инструмент | Что делают школьники |
|---|---|---|
| 01 · Сбор | `http://localhost:8000/collect.html` | Произносят 4 команды, сохраняют WAV `dataset/up/01.wav`, `dataset/down/01.wav` и т.д. |
| 02 · Признаки | `http://localhost:8000/visualize.html` | Выбирают запись и смотрят волновую форму, усреднённый спектр, спектрограмму и мел-спектрограмму |
| 03 · Обучение | `http://localhost:8000/train.html` | Нажимают «Обучить», следят за извлечением MFCC, смотрят PCA, проверяют новую запись и её ближайших соседей |
| 04 · Игра | `http://localhost:8000/index.html` | Произносят слова — обученный ими классификатор перемещает робота по лабиринту |

**Технически это учебный распознаватель 4 коротких команд (keyword spotting), а не полноценный ASR для произвольной речи.** 16 кГц PCM WAV → STFT → мел-фильтры → MFCC (26 агрегированных признаков) → StandardScaler + k-nearest neighbors (k=3). Подготовленное ПО выполняет вычисления, но *обучающие записи и классы модели создают участники*. Система не нуждается в Vosk, Whisper, внешнем распознавании речи или подключении к API.

### 1. Однократная подготовка (с интернетом)

Рекомендуется Python 3.10–3.13. Из папки проекта:

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

**Windows PowerShell**

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для Mac разреши Chrome доступ к микрофону (настройки сайта и **Системные настройки → Конфиденциальность и безопасность → Микрофон**).

### 2. Запуск в день занятия (интернет уже не нужен)

**macOS / Linux**

```bash
source .venv/bin/activate
python lab_server.py
```

**Windows**

```powershell
.venv\Scripts\python.exe lab_server.py
```

Открой Chrome **http://localhost:8000/collect.html**. Если ранее работал старый `server.py` с Vosk на порту 8000, сначала останови его (`Ctrl+C`). Работай через localhost, **не открывай HTML как файл**. Сервер слушает только `127.0.0.1`; записи не покидают ноутбук.

В браузере открой `http://localhost:8000/train.html`, нажми **«Обучить модель»**.
Страница покажет реальный прогресс обработки записей, сохранит модель в `models/keyword_classifier.npz` и построит проекцию PCA. На той же странице можно записать **новую** команду: модель покажет предполагаемый класс и три ближайшие записи с расстояниями в 26-мерном пространстве признаков.

Обучение выполняется локальным Python-сервером. **Jupyter и Colab не нужны.** После обучения открой `/index.html`: сервер автоматически подхватывает модель.

**Резервные варианты:** `python train_model.py` или `training.ipynb` в локальном Jupyter (по желанию). В Colab без интернета работать нельзя.

### 3. Сбор данных

В `collect.html` 4 карточки: **вверх / вниз / влево / вправо**. Нажми «Начать запись», скажи одно слово, нажми «Остановить и сохранить». Сервер сохраняет 16-битный PCM WAV, **16000 Hz, mono**, присваивает `01.wav`, `02.wav` ... в отдельной папке каждого класса. Минимум — 2 записи на класс, практически рекомендую 5–10 записей от разных школьников на класс. Ошибочную запись можно прослушать и удалить крестиком; следующий номер выбирается автоматически.

Папки создаются автоматически:

```text
dataset/
  up/     01.wav 02.wav ...
  down/   01.wav 02.wav ...
  left/   01.wav 02.wav ...
  right/  01.wav 02.wav ...
```

Нарочно попроси разных школьников записать свои примеры; длительные паузы автоматически подрезаются **для анализа и обучения**, а исходный WAV остаётся неизменным. Не нужно записывать много секунд тишины.

### 4. Визуализация

Открой `visualize.html`, выбери класс и номер файла. Python строит 4 графика локально. Рисунки спектра/спектрограммы масштабируются в децибелах и показывают энергию по частотам, а мел-спектрограмма — по 32 фильтрам. Это точные графики той же процедуры, из которой вычисляем MFCC-признаки для обучения.

**Отдельно для любого корректного WAV:**

```bash
python visualize_wav.py dataset/up/01.wav --out up-01.png
```

Входной WAV должен быть mono 16-bit PCM 16 kHz длительностью от 0.4 до 5.5 с. Для других форматов предварительно переконвертируй в эти параметры.

### 5. Если нужен Google Colab

Colab **не работает без интернета** и больше не требуется для мастер-класса. Ниже — только необязательный альтернативный способ обучения.

1. На `collect.html` нажми **«Скачать датасет ZIP (необязательно)»**.
2. Открой `training.ipynb` в [Google Colab](https://colab.research.google.com/).
3. Запусти первую кодовую ячейку. Она предложит загрузить `asr-dataset.zip`, в котором находятся WAV, `features.py` и `trainer.py`.
4. Выполни все ячейки: последняя скачает `keyword_classifier.npz`.
5. Положи его на своём компьютере в **`models/keyword_classifier.npz`** и открой страницу лабиринта.

`npz` хранит только численные массивы нормализованных признаков и метки — он переносим между Colab и локальным Python без проблем сериализации scikit-learn.

### 6. Игра

Четыре базовых правила уже заданы. Кнопка микрофона записывает слово и отправляет WAV на `/api/predict`. **Локально обученный классификатор** возвращает один из четырёх классов, а готовая логика лабиринта двигает персонажа.

Не добавляй в правила новые словесные команды, если не собираешься обучать для них дополнительные классы: нынешняя модель различает только эти 4 слова. Текстовое поле остаётся для отладки движения, но **не проверяет качество модели**.

## Тайминг 40 минут (1 ноутбук)

| Минуты | Сценарий |
|---|---|
| 0–4 | Покажи робота и задачу: как научить его отличать четыре слова? |
| 4–17 | 4 группы по очереди произносят свои слова. Цель: ≥5 WAV на класс (20 записей) |
| 17–24 | Выберите два WAV, сравните 4 представления звука, поговорите о мел-фильтрах |
| 24–30 | На `train.html` нажми «Обучить»; покажи прогресс, PCA и проверку новой записи |
| 30–40 | Открой лабиринт, по очереди попробуйте управлять роботом голосом |

Финальный отдельный сравнительный эксперимент не предусмотрен.

## Как подготовиться надёжно

- Пройди **полный сценарий на том же ноутбуке и микрофоне**, с которыми будешь выступать. После установки зависимостей выключи Wi‑Fi и проверь `collect.html`, `visualize.html`, `train.html` и `index.html`.
- На мастер-классе не начинай установку библиотек; заранее активируй виртуальное окружение, запусти локальный сервер и открой четыре этапа в браузере.
- Для резервного сценария заранее запиши собственные 20 WAV и скопируй папку `dataset` в безопасное место. Если понадобится вернуть резервные записи, выключи сервер и восстанови папку.
- Простой k-NN с несколькими записями может ошибаться при изменении громкости, голосов и скорости речи. **Ошибки не означают, что ноутбук неправильно запущен**; это ограничение модели и малого датасета. Модель всегда выбирает одну из четырёх меток, даже для посторонних слов.
- Записи голосов сохраняются на диске. Попроси согласие участников и школы; после занятия удали WAV, если они не нужны. Для младших школьников не собирай фамилии и иную идентифицирующую информацию.

## Структура

```text
asr-maze-lab/
├── collect.html, collect.js       # браузерный сборщик
├── visualize.html, visualize.js   # просмотр сигналов
├── recorder.js                    # захват микрофона и WAV-кодирование
├── workshop.css                   # оформление этапов 01–03
├── train.html, train.js            # обучение + PCA + ближайшие соседи в браузере
├── training_web.py                # фоновая локальная задача обучения и визуализации
├── training.ipynb                 # необязательный прежний вариант обучения
├── train_model.py                 # резервный запуск обучения без ноутбука
├── features.py                    # STFT, mel, MFCC, matplotlib
├── trainer.py                     # классификатор, PCA, рисунок kNN
├── lab_server.py                  # API только на localhost
├── index.html, app.js, style.css  # существующий лабиринт, новая модель
├── visualize_wav.py              # экспорт четырёх графиков в PNG
├── dataset/{up,down,left,right}/  # записи WAV
├── models/                        # обученная модель NPZ
└── tests/                         # интеграционные проверки, включая обучение через веб
```

Проверка серверных компонентов: `python -m unittest discover -s tests -v`.
